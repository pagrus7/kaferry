# Kaferry v0.9.0

> **Not recommended:** This release adds Kafka permission requirements and complexity outside Kaferry's intended scope.

Resume Kafka and archive copies without repeating committed output, with new progress storage and setup requirements.

## Changes

- Exactly-once delivery applies across Kafka and archive routes, including copies between Kafka clusters. Resuming the same job produces one committed output per selected input occurrence; equal values and overlapping archive records remain separate occurrences. Kafka output readers must use `isolation.level=read_committed`. Each source partition commits independently. [Delivery and recovery contract](https://github.com/pagrus7/kaferry/blob/v0.9.0/design/delivery.md).
- Kafka copies save authoritative progress in a compact-only topic: on the destination cluster for Kafka output, or the source cluster for archive capture. Source-group offsets no longer determine resume positions. `explain` and `status` read this progress without joining groups or writing.
- `kaferry run --recover-local` publishes committed files from a recovered capture disk after another worker takes over. Retain every disk containing committed output. [Recovery procedure](https://github.com/pagrus7/kaferry/blob/v0.9.0/docs/usage.md#recover-a-capture-disk-after-takeover).
- Archive capture rotates aged files during quiet input and enforces the open-file budget across source partitions. Saved progress can be reloaded after checkpoint chunk sizes change.

## Upgrade

- Stop all workers before replacing binaries. Saved Kafka progress and standalone replay checkpoints from v0.8.0 and earlier cannot be resumed; no migration is provided. New advisory Kafka metadata uses `kaferry:4;`, which older binaries reject. Use a new group for an independent copy; this can repeat records already present in the destination. Completed Avro archive files remain readable. [State compatibility](https://github.com/pagrus7/kaferry/blob/v0.9.0/design/delivery.md#state-format).
- Before any copy involving Kafka, provision `kaferry-progress` with `cleanup.policy=compact` and no `delete` policy, or set `worker.progress_topic` to another prepared topic. Grant progress-topic access, configuration reads, partition growth and transactional-ID permissions. [Setup](https://github.com/pagrus7/kaferry/blob/v0.9.0/docs/usage.md#prepare-authoritative-progress) · [Permissions](https://github.com/pagrus7/kaferry/blob/v0.9.0/docs/usage.md#permissions).
- Retain committed output and authoritative progress together. Move replay `.eos` bindings with their checkpoint directory, and move complete capture directories including hidden state. Missing or incompatible authority for an initialized job stops the copy.

## Known issues

- franz-go v1.22.2 misreads Kafka record timestamps outside roughly 1677–2262. [Exact bounds and Kafka timestamp defaults](https://github.com/pagrus7/kaferry/blob/v0.9.0/design/client-compatibility.md#kafka-input-timestamps).
- AWS IAM signing and credential rotation are covered by component tests; release tests do not contact MSK.

## Downloads

Linux AMD64/ARM64 static binaries and macOS AMD64/ARM64 binaries. Archives include `LICENSE` and `THIRD_PARTY_NOTICES.txt`. Assets include the archive tutorial bundle, `qualification.md`, per-platform Go build information, SPDX SBOMs, provenance and SBOM attestation bundles, and `SHA256SUMS`.

Linux container images are published as `ghcr.io/pagrus7/kaferry:v0.9.0`. Source installation requires Go 1.26+: `CGO_ENABLED=0 go install github.com/pagrus7/kaferry/cmd/kaferry@v0.9.0`.
