# Kaferry v0.12.0

Protect saved progress when a Kafka destination topic is deleted and recreated, and expose saved positions for recovery.

## Changes

- Copies to Kafka bind saved progress to the destination topic UUID. Restarting after topic recreation rejects the old progress instead of silently resuming past records missing from the new destination.
- On a query fingerprint mismatch, `status --json` reports `unknown` and retains source-validated saved positions, fingerprints and windows for inspection. Invalid metadata or a changed source UUID withholds positions. [Recovery procedure](https://github.com/pagrus7/kaferry/blob/v0.12.0/docs/usage.md#recover-after-destination-topic-recreation).

## Upgrade

- Stop all workers before replacing binaries. Existing Kafka-destination groups and replay checkpoints from v0.11.0 are incompatible, even when the destination topic has not changed. Use a new group; it can copy records already present at the destination. The recovery procedure covers inspecting old positions and choosing explicit Kafka source offsets and fixed timestamp bounds. Kaferry does not migrate saved progress automatically.
- Progress for archive destinations remains compatible with v0.11.0.

## Known issues

- Destination identity is checked at startup. Topic recreation during a running copy can still cause partial output or replacement-topic writes before detection. [Kafka output limits](https://github.com/pagrus7/kaferry/blob/v0.12.0/design/decisions.md#kafka-output).
- franz-go v1.22.2 misreads Kafka record timestamps outside roughly 1677–2262. [Exact bounds](https://github.com/pagrus7/kaferry/blob/v0.12.0/design/client-compatibility.md#kafka-input-timestamps).
- AWS IAM signing and credential rotation have component coverage; release tests do not contact MSK. Multi-day endurance and deployment-specific authentication require separate qualification.

## Downloads

Linux AMD64/ARM64 static binaries and macOS AMD64/ARM64 binaries. Archives include `LICENSE` and `THIRD_PARTY_NOTICES.txt`. Assets include the archive tutorial bundle, qualification and compatibility summaries, per-platform Go build information, SPDX SBOMs, provenance and SBOM attestation bundles, and `SHA256SUMS`.

Linux container images are published as `ghcr.io/pagrus7/kaferry:v0.12.0`. Source installation requires Go 1.26+: `CGO_ENABLED=0 go install github.com/pagrus7/kaferry/cmd/kaferry@v0.12.0`.
