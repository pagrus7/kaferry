# Kaferry v0.13.0

Expand Kafka fault qualification and retry recoverable destination disconnections.

## Changes

- Add fault checks on three-broker Kafka 4.4.0 clusters with plaintext listeners: source and destination leader loss, rolling restarts, too few destination in-sync replicas, destination network cuts, latency, bandwidth limits and delayed closes.
- Check worker death during rebalances and scaling from one to three workers and back. A worker isolated from its coordinator must not save stale progress after losing its partitions. Independent record reconciliation and saved-progress sampling accompany the fault tests. [Scenarios and limits](https://github.com/pagrus7/kaferry/blob/v0.13.0/docs/design/qualification.md#replicated-faults).
- Add load profiles for values near the topic size limit, Zipf-distributed hot keys, heavy headers, tombstones on compacted topics and all five source compression codecs. Measurements retain their profile parameters.
- Run rebalance-churn checks against the selected executable, including release archives. Source-retention checks cover out-of-range copying failures and reported expired saved positions. The stable diagnostic labels `poll source`, `save progress` and `expired source position` identify copy operations and reported retention gaps.
- Retry destination connection EOFs during API negotiation within the existing request and delivery limits. Unrecovered delivery failures stop copying.

## Upgrade

- Source installations use `CGO_ENABLED=0 go install github.com/pagrus7/kaferry/src/cmd/kaferry@v0.13.0`. Tags v0.12.0 and older retain the original `cmd/kaferry` path. Downloaded binaries and container commands keep their names.
- Application code and tests now live under `src/`, and repository tools under `tools/`. Run Python tools from the repository root as `python3 -m tools.CATEGORY.MODULE`; start fixtures with `make broker`.

## Known issues

- Published-binary qualification does not cover coordinator-broker death during a rebalance. The case stopped while restoring required broker audit logging, before recovery could be checked.
- Destination topic identity is checked at startup. Recreation during a running copy can still cause partial output or replacement-topic writes before detection. [Kafka output limits](https://github.com/pagrus7/kaferry/blob/v0.13.0/docs/design/decisions.md#kafka-output).
- franz-go v1.22.2 misreads Kafka timestamps outside roughly 1677–2262. [Exact bounds](https://github.com/pagrus7/kaferry/blob/v0.13.0/docs/design/client-compatibility.md#kafka-input-timestamps).
- Release authentication checks do not contact MSK; AWS IAM signing and credential rotation have component coverage. [Client coverage](https://github.com/pagrus7/kaferry/blob/v0.13.0/docs/design/client-compatibility.md#tested-configurations).
