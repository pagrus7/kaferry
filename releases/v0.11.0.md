# Kaferry v0.11.0

Make timestamp stopping explicit, distinguish source completion from worker limits, and publish compatibility evidence for the release binary.

## Changes

- `MAX_OUT_OF_ORDER` now defaults to `OFF`. Timestamp-bounded Kafka copies still use the default five-minute `MAX_STALENESS` allowance, but no longer stop early because a record's timestamp passes a disorder threshold unless explicitly configured.
- `status` distinguishes `complete`, `complete_within_staleness` and `limit_reached` instead of reporting all saved stops as `stopped`. Completion describes source processing; it does not verify destination data or guarantee exactly-once delivery. [Status meanings](https://github.com/pagrus7/kaferry/blob/v0.11.0/docs/reference.md#saved-status).
- Archive replay creates the default `~/.kaferry/checkpoints` directory when needed. A configured checkpoint directory must already exist.
- Release assets include `compatibility.json` and `compatibility.md`, identifying the broker/authentication matrix exercised against the exact Linux AMD64 binary. [Qualification scope and limits](https://github.com/pagrus7/kaferry/blob/v0.11.0/design/qualification.md).

## Upgrade

- Stop workers before replacing binaries. Timestamp-bounded Kafka queries that relied on implicit disorder stopping have a different saved-progress identity. To resume their existing groups with the former semantics, explicitly set `MAX_OUT_OF_ORDER` to the former `MAX_STALENESS` allowance (five minutes by default). To adopt `OFF`, use a new group; this can copy records already present at the destination. [Completion and saved identity](https://github.com/pagrus7/kaferry/blob/v0.11.0/design/decisions.md#completion).
- Update scripts that expect the `stopped` status verdict. `limit_reached` now exits 7; rerun the same job for another worker record allowance. [Exit codes](https://github.com/pagrus7/kaferry/blob/v0.11.0/docs/reference.md#cli-and-exit-codes).
- Saved state from v0.9.0 remains unsupported; follow the [v0.10.0 upgrade instructions](https://github.com/pagrus7/kaferry/blob/v0.11.0/releases/v0.10.0.md#upgrade).

## Known issues

- franz-go v1.22.2 misreads Kafka record timestamps outside roughly 1677–2262. [Exact bounds and Kafka timestamp defaults](https://github.com/pagrus7/kaferry/blob/v0.11.0/design/client-compatibility.md#kafka-input-timestamps).
- AWS IAM signing and credential rotation are covered by component tests; release tests do not contact MSK. Multi-day endurance and deployment-specific authentication require separate qualification.

## Downloads

Linux AMD64/ARM64 static binaries and macOS AMD64/ARM64 binaries. Archives include `LICENSE` and `THIRD_PARTY_NOTICES.txt`. Assets include the archive tutorial bundle, qualification and compatibility summaries, per-platform Go build information, SPDX SBOMs, provenance and SBOM attestation bundles, and `SHA256SUMS`.

Linux container images are published as `ghcr.io/pagrus7/kaferry:v0.11.0`. Source installation requires Go 1.26+: `CGO_ENABLED=0 go install github.com/pagrus7/kaferry/cmd/kaferry@v0.11.0`.
