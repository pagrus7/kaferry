# Kaferry v0.2.1

Adds a workaround for a Kafka-source startup crash and SBOMs and attestations for downloads.

## Changes

- Turn tested group-coordinator timeouts at Kafka-source startup into a normal error (exit `1`) instead of a librdkafka crash.
- Update the Confluent Go client and bundled librdkafka from 2.15.0 to 2.16.0; build with Go 1.26.9.
- Require `HOME` only when a file source uses the default checkpoint directory.
- Add SPDX SBOMs, librdkafka inventory and license text, and GitHub attestations to release assets.

## Upgrade

- Stop all workers sharing a query/group, then replace the binary. SQL, configuration, saved progress and v1 archives remain compatible. Keep the existing checkpoint directory when resuming file sources.

## Known issues

- The workaround makes tested coordinator timeouts fail normally, but the [librdkafka bug](https://github.com/confluentinc/librdkafka/pull/5397) can still crash Kafka-source startup in other cases. Cleanup delayed past the native timeout remains a risk; other upstream error paths are not all verified. Whether startup fails normally or crashes, the worker copies nothing and leaves saved progress unchanged; rerun after coordinator recovery. Bundled librdkafka 2.16.0 lacks the upstream fix. Production frequency is unknown. [Details](https://github.com/pagrus7/kaferry/blob/v0.2.1/design/client-compatibility.md#known-issues).
- Native commit and close have no overall deadline; use a supervisor stop timeout if shutdown must be bounded.

## Downloads

Linux AMD64/ARM64 (glibc 2.34+) and macOS 14+ ARM64 archives. Each platform also has Go build information, an SPDX SBOM, librdkafka inventory and license text, and provenance and SBOM attestation bundles. `SHA256SUMS` provides checksums for these files. [Verification](https://github.com/pagrus7/kaferry/blob/v0.2.1/design/components.md#release-evidence).
