# Kaferry v0.2.0

Renames the command and downloads to Kaferry and makes file-source checkpoint setup explicit.

## Changes

- Publish `kaferry` binaries and the `github.com/pagrus7/kaferry` Go module.
- Require file-source checkpoint directories to exist; strengthen worker ownership checks.
- Preserve v1 CBOR archives and saved v1 Kafka commit metadata.

## Upgrade

- Stop all workers sharing a query/group before upgrading; mixed versions are unsupported.
- To resume a file-source job, set `worker.checkpoint_dir` to the existing directory's absolute path. Missing progress can replay Kafka output or prevent resuming file output. Kaferry does not discover or migrate progress. If moving it, move checkpoint and stable `.lock` files together with workers stopped.
- For new file-source jobs, create the default directory with `mkdir -p ~/.kaferry/checkpoints`.
- Update generated-group ACLs, client-ID quotas and monitoring for the `kaferry-` prefix. Existing named Kafka groups remain compatible.
- Temporary files left by interrupted earlier publications are no longer removed automatically; inspect them only after stopping writers.

## Known issues

A [librdkafka bug](https://github.com/confluentinc/librdkafka/pull/5397) can crash Kafka-source startup during coordinator failures. This version uses client 2.15.0 and has no timeout workaround. The affected checks run before copying; production frequency is unknown. Native commit and close have no hard overall shutdown deadline.

See the [client limits and permissions for this version](https://github.com/pagrus7/kaferry/blob/v0.2.0/design/client-compatibility.md).

## Downloads

Linux AMD64/ARM64 (glibc 2.34+) and macOS 14+ ARM64 archives, `SHA256SUMS` for the archives and Go build information.
