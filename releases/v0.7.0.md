# Kaferry v0.7.0

Copy fixed offset ranges and choose independent timestamp completion limits.

## Changes

- Kafka timestamp ranges start copying immediately. `MAX_STALENESS` controls when wall time captures partition ends; `MAX_OUT_OF_ORDER` controls when record timestamps can finish a partition. Both default to five minutes for Kafka, and either can be `OFF`. [Completion guarantees and assumptions](https://github.com/pagrus7/kaferry/blob/v0.7.0/design/decisions.md#completion).
- `WHERE RECORD_OFFSET < LATEST` copies through each partition's fixed readable committed end. Numeric offset ranges and grouped per-partition ranges are supported; resume reuses saved ends.
- Archive replay accepts original-offset ranges and optional `MAX_OUT_OF_ORDER` per original source partition. Timestamp stopping is off by default, so replay examines its fixed file selection.
- `ARCHIVE 'directory'` names archive sources and destinations. The usage guide includes preparation, stopping, resuming and checking results, with source and sink settings grouped in the reference.
- Downloads include a runnable archive tutorial bundle and `qualification.md`, which identifies the tested source, binary and release scenarios.

## Upgrade

- Stop workers before upgrading. Replace `FILE avro('directory')` with `ARCHIVE 'directory'` and source `CUTOFF` with `MAX_STALENESS`. Review the timestamp assumptions and set `MAX_OUT_OF_ORDER` independently when needed. [SQL examples and defaults](https://github.com/pagrus7/kaferry/blob/v0.7.0/design/grammar.md#valid-examples).
- Kafka jobs with an upper timestamp bound saved by earlier releases need a new `GROUP`. Unchanged unbounded Kafka jobs, archive data and unchanged archive replay checkpoints remain compatible. Changing timestamp allowances or offset criteria needs a new group.
- Captured Kafka ends use commit metadata version 3; older binaries cannot resume those jobs. `explain --json` uses report version 2; update consumers of that output.

## Known issues

- franz-go v1.22.2 misreads Kafka record timestamps outside ±9,223,372,036,854 Unix milliseconds. [Scope and Kafka 4+ defaults](https://github.com/pagrus7/kaferry/blob/v0.7.0/design/client-compatibility.md#known-issues).

## Downloads

Linux AMD64/ARM64 static binaries and macOS AMD64/ARM64 binaries. Archives include `LICENSE` and `THIRD_PARTY_NOTICES.txt`. Each platform also has Go build information, an SPDX SBOM, and provenance and SBOM attestation bundles; `SHA256SUMS` covers the release assets.

Linux container images are published as `ghcr.io/pagrus7/kaferry:v0.7.0`. Source installation requires Go 1.26+: `CGO_ENABLED=0 go install github.com/pagrus7/kaferry/cmd/kaferry@v0.7.0`.
